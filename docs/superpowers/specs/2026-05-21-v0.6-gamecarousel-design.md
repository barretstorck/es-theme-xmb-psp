# v0.6 — Boxart Gamecarousel Gamelist, Square Cross Anchor, Larger Clock

**Status:** Design approved 2026-05-21. Implementation pending.

**Builds on:** v0.5 (XMB cross layout). v0.5's system carousel, colorsets, wave
background/motion, `gamecount` subset, Roboto Condensed font, and the `detailed`
gamelist view are the starting point and are otherwise unchanged.

## Goal

Three changes, implemented in this order:

1. **Square cross anchor** — reposition the selected-system anchor so the empty
   space in the top-left corner of the screen is a true pixel-square.
2. **Larger clock** — enlarge the top-right time.
3. **Boxart gamecarousel** — add a second gamelist style: a vertical carousel of
   game boxart, alongside the existing text-list gamelist. Both gamelist styles
   share a redesigned right-side info panel.

### Context / constraints

- batocera-emulationstation, `formatVersion 7`, Knulli on TrimUI Brick, 1024x768.
- This build has repeatedly diverged from documented behaviour (`logoPos`
  crashes the carousel render; `systemInfo` will not render the system name).
  v0.6 carries several known-unknowns (see that section) to verify on-device
  early — the gamecarousel work should open with a spike.

## Current state

The shared cross anchor in `_inc/common.xml` is `crossX = 0.24`, `crossY = 0.33`
(normalized), `captionY = 0.44`. The selected system icon is centred on
`crossX`/`crossY` in the system view and both gamelist views. The clock is
`<datetime name="clock">` at `fontSize 0.030` in `_inc/system.xml` and
`_inc/gamelist.xml`. The gamelist is a single `detailed` view: a text `<textlist>`
game column on the left, a right panel of `md_name` + `md_image` boxart +
`md_releasedate` / `md_players` / `md_rating`.

## Change 1 — Square cross anchor

### Rule

The selected system icon's **top-left corner** must be equidistant, in screen
pixels, from the screen's top edge and its left edge — i.e. the empty space in
the top-left corner of the screen is a true square, with the selected system
icon at its bottom-right corner.

### New state

- **`crossX` is unchanged** (`0.24`) — the horizontal position is already good.
- **`crossY` moves up** so the selected icon's top edge sits the same number of
  pixels from the screen's top as its left edge is from the screen's left.
- The rendered size of the scaled, selected carousel icon on this build is not
  known precisely, so **`crossY` is tuned on-device**: screenshot the system
  view, measure the selected icon's top-left corner offsets, adjust `crossY`,
  repeat until top-offset == left-offset (pixels).
- The system carousel container's `pos.y` in `_inc/system.xml` is hand-computed
  from the new `crossY` (theme XML has no arithmetic; the container is
  positioned by hand and commented with its derivation, as in v0.5).

The anchor is shared, so this moves the selected icon in the system view and
both gamelist views together. Purpose: a cleaner XMB-style corner and more room
for the game column.

---

## Change 2 — Larger clock

The top-right time is `<datetime name="clock" extra="true">` (`fontSize 0.030`)
in `_inc/system.xml` and `_inc/gamelist.xml`. Enlarge the font; the exact size is
tuned on-device for legibility and proportion. Position (`pos 0.88 0.03`,
right-aligned) is adjusted only if the larger text needs it.

The battery and WiFi indicators are **not** changed — see Deferred work.

## Change 3 — Boxart gamecarousel gamelist

### Two gamelist views

The theme provides both gamelist styles:

- **`detailed`** — the existing text-list gamelist (game names in a vertical
  `<textlist>`).
- **`gamecarousel`** — NEW: a vertical `<gamecarousel>` of game boxart tiles.

The user switches between them via EmulationStation's built-in **Gamelist View
Style** setting (per-system or global). This is *not* a theme subset — a subset
(like `colorset` or `gamecount`) swaps styling within a view, it cannot swap the
view *type*. The native ES view-style setting is the switch. See Known-unknown 2.

### The `gamecarousel` element

A `<gamecarousel>` element in the new `gamecarousel` view:

- `type` = `vertical` — a vertical strip of tiles.
- `imageSource` = `image` — each tile shows the game's boxart.
- positioned as the game column, centred on `crossX`, unfurling downward below
  the system icon + caption.
- the selected tile is enlarged via `logoScale`; tile size (`logoSize`), visible
  count (`maxLogoCount`), and spacing are tuned on-device.

### Shared right info panel

Defined **once** in a shared `<view name="detailed,gamecarousel">` block so both
gamelist views render an identical right panel and cannot drift apart. Top to
bottom:

- `md_name` — game title.
- `md_rating` — star rating.
- `md_video` — shows the game's screenshot still, then plays the preview video
  after a 5-second delay (`<delay>5</delay>` on the video element).
- `md_description` — the scrolling description text.

This **replaces** the `detailed` view's current right panel (the big `md_image`
boxart and the `md_releasedate` / `md_players` / `md_rating` rows). The Released
and Players fields are dropped; the big boxart is dropped (the carousel tiles, or
in the text-list view the names, plus the video, cover the visual need).

### Continuity

Both gamelist views keep the pinned system icon (`logo`) + system-name caption
(`systemName`) at the cross anchor, plus the wave background and clock — the XMB
cross still reads continuously from the system view into either gamelist style.

## Known unknowns

Verify on-device early. The gamecarousel implementation should **open with a
spike** — a bare `gamecarousel` view with one `md_*` element — to settle 1-3
before the full panel is built.

1. **Does the `gamecarousel` view host `md_*` / `<video>` elements?** The entire
   shared right panel depends on this. The view has a selected game, so it
   should — but unverified on this build.
2. **How ES selects the `gamecarousel` view** — it must be reachable via the
   Gamelist View Style setting. If ES's "automatic" mode will not pick it,
   switching becomes a manual ES setting (as the transition style was).
3. **`gamecarousel` rendering quirks** on this build.
4. **The `md_video` still-frame source** — confirm it shows the *screenshot*
   (not boxart) before the 5-second video, and how the delay/snapshot is set.
5. **`imageSource` fallback** for an unscraped game — low priority; the design
   assumes a scraped library per the user.
6. **The exact `crossY`** for the square (Change 1) — pure on-device tuning.

## Deferred work — battery / WiFi resizing

Enlarging the top-right **battery and WiFi indicators** is **deferred to a future
session.** The batocera-ES theme documentation exposes no battery / network /
wifi elements, so it is not resizable through the documented theme API. However,
the user has seen other themes resize these indicators — so a future session
should **review other batocera / Knulli themes** to learn how (an undocumented
element, a different mechanism, a global setting, etc.). For v0.6, only the clock
(Change 2) is enlarged.

## Testing

On-device, via `scripts/deploy.sh` (sync -> pause -> screenshot-check -> reload)
and `scripts/ui.sh`, reading screenshots — the v0.5 workflow.

- **Change 1:** screenshot the system view; measure the selected icon's top-left
  corner — top-offset must equal left-offset (pixels). Iterate `crossY`.
- **Change 2:** the clock is visibly larger and legible; no overlap with the
  battery/WiFi indicators.
- **Change 3:** spike first (unknowns 1-3). Then: the `gamecarousel` view renders
  boxart tiles in a vertical column; the shared right panel shows title / rating
  / video / description in BOTH gamelist views; switching the ES Gamelist View
  Style setting flips between the text list and the boxart carousel; the XMB
  cross stays continuous (pinned icon + caption) in both.

## Out of scope

- Battery / WiFi resizing (deferred — see Deferred work).
- Changes to the system carousel's horizontal layout, the colorsets, the wave,
  or the `gamecount` subset.
- Game-launch transitions; the `grid` and `basic` gamelist view types.
