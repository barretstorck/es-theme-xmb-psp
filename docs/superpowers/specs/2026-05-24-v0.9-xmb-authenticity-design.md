# v0.9 XMB Authenticity — Design Spec

**Date:** 2026-05-24
**Branch:** `feat/v0.9-xmb-authenticity`
**Predecessor:** v0.8.2 (multi-aspect-ratio support, shipped)

## Goal

Tighten the theme's visual fidelity to the PSP XrossMediaBar (XMB) reference in two targeted areas: add a **battery indicator** to the top-right status bar, and add a **soft colored halo** behind the selected system carousel icon. Both are signature PSP XMB visual cues that the theme currently lacks.

## Context — what was already authentic

A v0.9 audit confirmed the theme already matches the PSP XMB on most elements:

- Horizontal category row, selected icon at the cross-axis intersection — ✓ matches
- Selected icon goes bright white, unselected dim — ✓ matches
- Selected icon **renders larger than its neighbours** (`logoScale=1.5` → selected at 1.5×, neighbours fade smoothly to 1.0× per `CarouselComponent.cpp:469-473`) — ✓ matches PSP "unselected shrink"
- Category caption directly below the icon — ✓ matches
- Monthly color palette (12 colorsets) — ✓ matches concept
- Multi-layer translucent wave (3 layers + tinted base) — ✓ matches concept
- Navigate / select / back chimes — ✓ matches
- Cross layout (horizontal ↔ vertical axes) — ✓ matches

The two gaps addressed here are the visible-on-startup ones with feasible engine support.

## Context — what we deliberately don't fix in v0.9

These were considered and dropped:

| Item | Reason |
|---|---|
| Date display in top-right (PSP shows `26/6` next to clock) | `<clock>` is hardcoded to time-only formats (`ClockComponent.cpp:31-34`); `<datetime>` is registered for gamelist metadata, not `screen` view. No theme XML path. |
| 12-hour AM/PM time format | Toggled by user's ES setting, not by theme. |
| Inline vertical item column on system view (PSP's defining "items appear under the selected category" behavior) | ES architecturally separates `system` view from `gamelist` view; would require non-trivial workaround. Carryover for a future revision. |
| Selected-icon scale enhancement | Already matches PSP via `logoScale=1.5`; the v0.9 audit's initial "we don't have scale" claim was a false positive. |
| Wave softening / amplitude tuning | Cosmetic polish, lower visible impact. Carryover. |
| PSP wordmark top-left | Optional brand mark, low impact. Carryover. |
| Custom Sony-look font | Roboto Condensed is a reasonable open-source approximation; bundled Ubuntu Condensed isn't measurably closer. Out of scope. |
| ES menu re-skin updates | Out of scope. |

## Architecture

Two independent additions, both layered onto the existing v0.8 multi-aspect-ratio structure:

1. **Battery glyph** — a new `<image name="batteryIcon">` in the existing `screen` view block of `_inc/common.xml`, alongside the existing `<clock>`. Uses the ES-native `batteryIcon` element which auto-cycles through 6 state PNGs as battery level changes. Auto-hides on devices without a battery (e.g., the Docker harness).

2. **Selected-icon halo** — a new `<image name="selectedHalo" extra="true">` in `_inc/system.xml`, layered behind the carousel logos at the cross intersection (`crossX`/`crossY`). The selected icon scrolls *through* the static halo as the carousel rotates, producing visually equivalent output to a per-icon halo without requiring per-icon artwork. Tinted with `${accent}` so it picks up the monthly colorset.

Both additions sit on top of v0.8's per-aspect-ratio variable system. The battery position is in normalized screen coordinates and reads correctly across all 5 ratios with no overrides. The halo follows the existing `crossX`/`crossY` anchors and may need per-ratio size overrides only if visual checks reveal a problem.

## Assets

### Battery icon set — `art/battery/`

Six PNGs corresponding to ES's hardcoded battery-state slots:

| File | ES slot | State | Visual |
|---|---|---|---|
| `battery-empty.png` | `empty` | <5% | Outline + 0 segments + optional `!` mark |
| `battery-25.png` | `at25` | 5–25% | Outline + 1 filled segment |
| `battery-50.png` | `at50` | 25–50% | Outline + 2 filled segments |
| `battery-75.png` | `at75` | 50–75% | Outline + 3 filled segments |
| `battery-full.png` | `full` | >75% | Outline + 3 filled segments (matches at75 in PSP) |
| `battery-incharge.png` | `incharge` | charging | Outline + lightning bolt overlay |

- **Source size:** 80×40 px (2:1 aspect ratio, matching the PSP reference image)
- **Style:** White outline + white segment fill, transparent background. Tinted at runtime via `<color>${textPrimary}</color>` (so it always matches the clock color, including future colorset overrides).
- **Generator:** `scripts/gen-battery-icons.py` (PIL-based, same pattern as `wave-layer-*.png`). Run once per asset change; output is committed alongside the script.

### Selected-icon halo — `art/halo.png`

A single PNG:

- **Source size:** 256×256 px
- **Style:** White-to-transparent **radial gaussian** glow. White core covers ~30% of the radius; soft tail to 100%.
- **Runtime tint:** `<color>${accent}</color>` — January Blue → blue halo, May Red → red halo, etc.
- **Generator:** `scripts/gen-halo.py` (PIL-based). Committed.

## Theme XML changes

### `_inc/common.xml`

Add two new variables to the existing `<variables>` block:

```xml
<haloW>0.18</haloW>
<haloH>0.24</haloH>
```

(Sized slightly larger than `sysIconMaxW × logoScale` and `sysIconMaxH × logoScale` so the halo extends just past the selected icon's edges.)

In the existing `<view name="screen">` block:

- Modify the `<clock>` element: change `<pos>0.84 0.03</pos>` → `<pos>0.78 0.03</pos>` to make room for the battery glyph to the right.
- Add a new `<image name="batteryIcon">` sibling:

```xml
<image name="batteryIcon">
  <pos>0.94 0.03</pos>
  <origin>0 0</origin>
  <maxSize>0.05 0.04</maxSize>
  <color>${textPrimary}</color>
  <empty>./art/battery/battery-empty.png</empty>
  <at25>./art/battery/battery-25.png</at25>
  <at50>./art/battery/battery-50.png</at50>
  <at75>./art/battery/battery-75.png</at75>
  <full>./art/battery/battery-full.png</full>
  <incharge>./art/battery/battery-incharge.png</incharge>
</image>
```

### `_inc/system.xml`

Add a new `extra="true"` image, before the existing `<carousel>` so `zIndex` ordering reads naturally in the file:

```xml
<image name="selectedHalo" extra="true">
  <path>./art/halo.png</path>
  <pos>${crossX} ${crossY}</pos>
  <origin>0.5 0.5</origin>
  <maxSize>${haloW} ${haloH}</maxSize>
  <color>${accent}</color>
  <zIndex>3</zIndex>
</image>
```

### `zIndex` ordering on the system view

After this change, system-view stacking is:

| zIndex | Element |
|---|---|
| 0 | `waveBackground` (existing) |
| **3** | **`selectedHalo` (new)** |
| 5 | `systemcarousel` |
| 6 | `systemInfo`, `logo` |
| 7 | `systemName` |

The halo sits above the wave, below the carousel logos and captions — exactly where the PSP halo sits.

### Known caveat — carousel-scroll transition

The halo is an `extra="true"` element, so it inherits the documented carousel-scroll quirk: on system change, it slides briefly with the transition and snaps back. This is the same behavior `waveBackground` and `systemName` have, accepted since v0.3. The halo doesn't make this worse.

### Per-aspect-ratio overrides

None needed by default. The halo is anchor-relative (tracks `crossX`/`crossY`, which already have per-ratio overrides for 16:9 and 1:1), and `haloW`/`haloH` are normalized.

If visual verification reveals the default halo size looks wrong at a specific ratio (e.g., too small at 1:1 where the selected icon scales larger), add per-ratio overrides to the corresponding `_inc/aspect-*.xml` file — but only if observed.

## Verification

Following the v0.8 P7 vision-based comparison methodology (harness output isn't byte-deterministic due to wave animation and wall-clock).

| Check | Where | Method |
|---|---|---|
| Battery icon renders at all | TrimUI Brick (on-device) | Visual — confirm icon appears top-right in correct state |
| Battery icon hides on no-battery devices | Docker harness | Render `system` view; confirm no battery glyph (harness reports no battery via `Utils::Platform::queryBatteryInformation`) |
| Battery + clock both legible | TrimUI Brick + harness | Visual; no clipping or overlap at all 5 ratios |
| Halo renders behind selected icon | Docker harness — system view × 5 ratios × 2 colorsets | Vision check — halo visible, tinted with `${accent}` |
| Halo scales correctly across aspect ratios | Docker harness | Confirm defaults look right at 4:3, 16:9, 3:2, 1:1, 8:7; add per-ratio overrides only if not |
| Halo doesn't break gamelist views | Docker harness | Render `detailed` and `gamecarousel`; confirm no halo on those views |
| Halo scroll transition is acceptable | Docker harness (visual) | Confirm it isn't *worse* than `waveBackground`'s known quirk |
| Clock still readable after position shift | Docker harness | Render all 5 ratios + 2 colorsets; confirm time isn't clipped |

**Colorset choice for verification:** January Blue (cool/dark) + May Red (warm/light). If both pass, the other 10 monthlies will too.

**On-device step is required for battery acceptance** — the harness cannot exercise it.

## Acceptance bar

- All 5 aspect ratios render the system view with the halo visible behind the selected icon
- Halo color matches `${accent}` (verifiable by swapping colorset)
- Battery icon appears correctly on TrimUI Brick across at least 2 charge states (e.g., charging + a discharge level)
- No regression on `detailed`, `gamecarousel`, or `menu` views
- All on-harness checks pass via vision-based comparison (no byte-pixel-diff bar)
- Plan executes via `superpowers:subagent-driven-development`; spec compliance + code quality reviews pass per task

## Out of scope (carryover for future revisions)

- Date display in the status bar (engine limitation)
- 12-hour AM/PM format enforcement (user setting, not theme)
- Inline vertical item column on system view (architectural)
- Wave softening / amplitude tuning (cosmetic)
- PSP wordmark top-left (cosmetic)
- Custom Sony-look font (no clear improvement available)
- ES menu re-skin updates
