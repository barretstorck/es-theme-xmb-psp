# v0.11 — Icon adoption (S1a + S1 + G10) Design

**Date:** 2026-05-27
**Branch:** `feat/v0.11-icon-adoption`
**Issues:** [#5 (S1)](https://github.com/barretstorck/es-theme-xmb-psp/issues/5), [#6 (S1a)](https://github.com/barretstorck/es-theme-xmb-psp/issues/6), [#19 (G10)](https://github.com/barretstorck/es-theme-xmb-psp/issues/19)

## Goal

Adopt RetroArch's `automatic` XMB icon set (CC-BY 4.0) as the bulk source of `art/system-icons/`. Cover ~110 hardware systems with PSP-style line-art outlines and ~13 branded auto-collection / tool icons with filled-graphic style — replacing the existing mixed-style Knulli icons everywhere the set has a match. The 42 uncovered shortnames retain their existing Knulli icons unchanged.

## Why this iteration

- **High visibility per effort.** Icons render on every screen of the carousel and at every cursor settle.
- **Low risk.** Pure asset swap — no theme-XML logic changes, no on-device crash surface, fully revertable via `git revert`.
- **Mechanical.** TSV + bash script + Docker render verification. Fits subagent-driven-development cleanly.
- **Unblocks four backlog items.** Sets the art direction for S3 (drop shadow), S4 (helpsystem glyphs), part of G5 (per-system media fallback icons), and S5 (selector chevron — needs same line weight).

## Out of scope (explicitly deferred)

- **Hand-drawn outlines for the 5 retro micros** (CoCo, Acorn Electron, Game & Watch, NEC PC-88, TI-99). They sit in the RA set's gap; keep current Knulli icons. Defer to a later art pass.
- **Branded per-app art for the 37 homebrew/ports** (`pico8`, `openbor`, `gzdoom`, `devilutionx`, `solarus`, `fallout1-ce`, `fallout2-ce`, `tyrian`, etc.). Defer to v0.12+.
- **S3 (drop shadow).** RA icons don't ship with shadows. Either pre-burn into the asset or live without; defer the decision.
- **S4 (helpsystem PSP glyphs).** Couples to S1 visually but needs separate art for cross/circle/square/triangle. Defer.
- **CHANGELOG.md.** Not part of this iteration; can be a separate small commit on `main` later.

## Workflow

1. **Author the mapping TSV.** Hand-edit `scripts/ra-mapping.tsv`. The audit's example rows are seeds; expected final count is in the 120–150 range (the audit's "~78% of 191" target plus family-alias rows that map multiple shortnames to the same RA file). One pass.
2. **Run import script.** `./scripts/import-ra-icons.sh` validates that `~/retroarch-assets/xmb/automatic/png/` exists (clear error and exit otherwise), then copies each RA source into `art/system-icons/<shortname>.png`. Idempotent. Any `MISS:` line in stderr indicates a TSV typo or missing RA source to fix.
3. **Render verification.** Run `./scripts/render.sh` for `--view system` AND `--view gamelist` AND `--view gamecarousel` at all 5 aspect ratios. The gamelist views need re-rendering because their pinned system icon uses the same `art/system-icons/<shortname>.png` files — those icons change too.
4. **Update screenshots.** Replace `docs/screenshots/{system,detailed,gamecarousel}-{4x3,16x9,3x2,1x1,8x7}.png` with the new renders (15 PNGs total).
5. **Update CREDITS.md.** Append the attribution block (full text in Attribution section below).
6. **Update README.md.** Reframe the "Known limitations" icon note (text in README section below).
7. **Bump version.** Update README header from `v0.10` to `v0.11`. Update wave commentary if needed (no structural changes expected).
8. **On-device check.** Deploy to the TrimUI Brick, navigate carousel, verify icons read at 1024×768 and no broken images appear.

## Verification criteria

- All 5 aspect-ratio renders complete without errors.
- New screenshots saved to `docs/screenshots/system-*.png` show the RA icons rendering at expected sizes (no over-large or over-small outliers).
- The 13 branded auto-collection icons are visually distinguishable from hardware silhouettes in the carousel (filled vs. outline style contrast is visible).
- No console warnings in `/tmp/es.log` indicate missing icon files for any shortname referenced by `es_systems.cfg`.
- On-device: carousel scrolls smoothly through systems; selected-icon scale-up and gamelist icon-pin still read correctly.

## Risk and rollback

- **Risk: RA icons render too small / too large compared to old Knulli set.** Mitigation: RA icons are 256×256, same canvas as the existing icons; size should be visually consistent. If not, the theme's `sysIconMaxW/H` variables in `_inc/common.xml` cap rendered size — no per-icon tweaking needed.
- **Risk: a TSV row points at a non-existent RA file.** Mitigation: `import-ra-icons.sh` prints `MISS:` lines for any unresolved source; surfaces typos immediately.
- **Risk: visual style clash between RA-covered and Knulli-uncovered icons.** This is *expected* by the design choice ("Keep existing Knulli icons in place"). Accept that 42 shortnames will retain their existing style; document the mixed-coverage state in README.
- **Rollback:** single `git revert` reverses the import. Knulli icons return verbatim because they were never deleted (just overwritten — git tracks the prior content).
