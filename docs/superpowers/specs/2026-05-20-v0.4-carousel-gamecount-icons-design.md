# v0.4 — Centered Carousel, Toggleable Game Count, Universal Icon Coverage

**Status:** Design approved 2026-05-20. Implementation pending.

**Builds on:** v0.3 (always-on PSP XMB wave background). v0.3's wave animation, colorset subset, and overall view structure are untouched.

## Goal

Three independent UX refinements on top of v0.3:

1. **PSP-pure centered carousel.** The systems carousel sits in the upper third today, with a system-name caption directly below. PSP XMB's category row is icon-only and vertically centered — match that.
2. **User-toggleable "X GAMES" counter.** Today the default ES game count renders below the carousel and the theme has no opinion on it. Add a `gamecount` subset (Hide / Show), default Hide.
3. **Universal icon coverage.** Today the carousel falls back to rendering the system shortname as text when no `<system>.png` is present in `art/system-icons/`. Every option should be an icon — no text in the carousel under any condition.

Each change is local and independent. None require touching `_inc/wave-motion.xml`, the colorset files, or the gamelist (detailed) view.

## Architecture

Three independent changes, each scoped to one file or one new pair of files:

| Change | File(s) |
|---|---|
| Carousel center + caption removal | `_inc/system.xml` (modify) |
| Gamecount subset | `theme.xml` (modify), `_inc/gamecount-hide.xml` (new), `_inc/gamecount-show.xml` (new) |
| Icon coverage | `art/system-icons/<missing-systems>.png` (new files), `CREDITS.md` (append section), `scripts/populate-fallback-icons.sh` (new) |

`README.md` gets a v0.4 banner, customization note about the new subset, and updated known-limits list.

## Tech stack

Unchanged from v0.3: batocera-emulationstation theme XML (`formatVersion 7`), PIL/Pillow only if `_default.png` needs touching (it doesn't in this scope), bash for the fallback script. No new runtime dependencies.

## Change 1 — Carousel centering

### Current state

In `_inc/system.xml`:

- `<carousel name="systemcarousel">` at `<pos>0 0.20</pos>` `<size>1 0.30</size>` — top edge y=0.20, height 0.30 → vertical center y=0.35
- `<text name="systemInfo">` at `<pos>0 0.50</pos>` `<size>1 0.06</size>` — caption rendering the selected system's display name below the carousel

### New state

- Carousel at `<pos>0 0.35</pos>` `<size>1 0.30</size>` — top edge y=0.35, height 0.30 → vertical center y=0.50
- `<text name="systemInfo">` element block deleted entirely

### Visual layout (1024×768, target device)

```
y=0.00 ┌──────────────────────────────────────────┐
       │                                  12:34   │   clock unchanged
y=0.15 │                                          │
       │                                          │
y=0.35 │  [ icon  icon  ICON  icon  icon ]        │   carousel top edge
y=0.50 │  ◄──── horizontal center ────►           │   carousel center (PSP-pure)
y=0.65 │                                          │   carousel bottom edge
       │                                          │
y=0.85 │                                          │   gamecount renders here today;
       │                                          │   Section 2 (gamecount subset) hides it by default
y=1.00 └──────────────────────────────────────────┘
```

### Rationale

PSP XMB's horizontal category row is icon-only — the highlighted (scaled) icon at the centerline IS the identifier, so a caption is redundant. Removing the caption also makes the theme language-neutral.

### Error handling

None required. Static positional change; no input validation, no failure modes.

### Testing

- Eyeball on device: carousel is vertically centered; no caption text appears below
- Navigation still works (carousel responsiveness is independent of position)
- No regression on detailed view (this change is isolated to `<view name="system">`)

## Change 2 — Gamecount subset

### theme.xml addition

After the existing `<subset name="colorset" ...>` block:

```xml
<subset name="gamecount" displayName="Game Count">
  <include name="Hide">./_inc/gamecount-hide.xml</include>
  <include name="Show">./_inc/gamecount-show.xml</include>
</subset>
```

The subset is the second `<subset>`. Both subsets coexist independently in `theme.xml`.

### Default behavior

Default = **Hide**. Per ES convention, the first `<include>` listed becomes the default when no user selection is stored. This matches PSP-pure aesthetic (icon-only) and is consistent with Change 1.

### File contents

**`_inc/gamecount-hide.xml`** — sets the gamecount element's visibility to false:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<theme>
  <formatVersion>7</formatVersion>
  <view name="system">
    <text name="GAMECOUNT_ELEMENT_NAME">
      <visible>false</visible>
    </text>
  </view>
</theme>
```

**`_inc/gamecount-show.xml`** — sets visible=true and styles the element to match the theme:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<theme>
  <formatVersion>7</formatVersion>
  <view name="system">
    <text name="GAMECOUNT_ELEMENT_NAME">
      <visible>true</visible>
      <pos>0 0.85</pos>
      <size>1 0.04</size>
      <fontPath>${fontLight}</fontPath>
      <fontSize>0.025</fontSize>
      <color>${textSecondary}</color>
      <alignment>center</alignment>
      <zIndex>5</zIndex>
    </text>
  </view>
</theme>
```

### Open implementation question

`GAMECOUNT_ELEMENT_NAME` is a placeholder. The actual ES element name in this batocera-emulationstation build is one of: `gamecount`, `systemInfo`, `gameCount`, or `gameCountAll`. The implementer must identify the real name as the first step of this change. Discovery sequence:

1. Read a few batocera/Knulli themes that explicitly style or hide the counter (e.g., CleanUI, Hexa, Artflix, Neon-Blast) and note which element name they target
2. If multiple themes use different names, prefer the one matching `xmb-menu-es-de` (our parent)
3. Confirm with a 30-second on-device test: deploy a `gamecount-hide.xml` candidate, observe whether the "X GAMES" string disappears

Replace `GAMECOUNT_ELEMENT_NAME` everywhere in both files once identified.

### Interaction with Change 1

Change 1 removes our `<text name="systemInfo">` element. Two possible behaviors:

- **(a)** The "X GAMES" counter is a separate ES element (`gamecount` or similar) → Change 1 has no effect on it → Change 2 still needs the hide override
- **(b)** "X GAMES" was being rendered by ES's default `systemInfo` (which our v0.3 override replaced with the system name only) → removing our override might restore the default → Change 2 still needs to override it back to hide-by-default

Either way, Change 2's hide override is needed. The investigation in Change 1 implementation should also note which case is in play, because it affects what `GAMECOUNT_ELEMENT_NAME` actually is.

### Testing

- Default install: carousel area is clean below — no "X GAMES" text
- Under UI Settings → Theme Configuration → Game Count → Show, "X GAMES" text appears below the carousel, styled per the show.xml block
- Switching back to Hide removes it again
- Colorset selection still works independently

## Change 3 — Universal icon coverage

### Problem

Today `_inc/system.xml` declares:

```xml
<image name="logo">
  <path>./art/system-icons/${system.theme}.png</path>
  ...
</image>
```

When the file doesn't exist, ES falls back to rendering `${system.theme}` as text in the carousel. We have 101 PNGs in `art/system-icons/` plus a `_default.png` that is currently unused. The user observed `ima…` (imageviewer) and `pyg…` (pygame) rendered as text on their device.

ES's `default` path attribute (per `THEMES.md` in batocera-emulationstation) only applies to metadata images (`md_image`), NOT to templated system paths. So the only way to guarantee every system shows an icon is to ensure `<system>.png` exists on disk for every system.

### Three-step pipeline

**Step 1 — Inventory.** Build the canonical Knulli system list and diff against `art/system-icons/` to produce the *missing list*.

Sources for the system list, in preference order:
1. Pull `es_systems.cfg` directly from the user's device (`/userdata/system/configs/emulationstation/es_systems.cfg` or `/usr/share/emulationstation/es_systems.cfg`). Authoritative for what the user actually has.
2. Fetch from Knulli's distribution repo (`knulli-cfw` org on GitHub) as a fallback if device access is unavailable.

Extract the `<name>` of each `<system>` entry. That string is what ES substitutes for `${system.theme}` at render time. (For some systems, `<theme>` overrides `<name>`; prefer `<theme>` when present, fall back to `<name>`.)

**Step 2 — Harvest from compatible themes.** For each missing system, look for an aesthetically-compatible icon in:

- **Primary source:** `anthonycaccese/xmb-menu-es-de` (GitHub) — direct parent theme, same CC-BY-NC-SA 2.0 license, same design language. Most likely to have icons that match our visual style.
- **Secondary sources (only if primary doesn't cover):** Other CC-BY-NC-SA 2.0 themes already documented in our existing CREDITS chain — XMB-Easy-Theme by InitialDin, or other ES-DE-derived theme sets. Check license compatibility before adopting from any theme not already in CREDITS.

Selection criteria when comparing candidate icons:
- Same aspect ratio family (square or near-square) as our existing icons
- Compatible color palette (PSP-style is bright/saturated; reject ultra-dark or muted icons)
- Compatible style (flat / silhouette icons match better than photographs or 3D renders)
- Reject anything where attribution chain is unclear

Track each harvested icon's source (which theme, which file in that theme) for crediting.

**Step 3 — Fallback to `_default.png`** for any system still missing after harvest.

`scripts/populate-fallback-icons.sh` (new file) — bash script that:
- Takes the canonical system list as input (either inline array, or reads from a checked-in `scripts/knulli-systems.txt`)
- For each system shortname in the list:
  - If `art/system-icons/<shortname>.png` exists → skip
  - Else → `cp art/system-icons/_default.png art/system-icons/<shortname>.png`
- Reports a summary: N systems already covered, M new fallback files created

The output PNG files are committed to the repo (per the "Static long-tail in repo" decision). This keeps the theme fully self-contained — no device-side scripting required at install.

### Credits

`CREDITS.md` gets a new section. Format:

```markdown
## Icon attribution

Most system icons in `art/system-icons/` are inherited from the parent theme chain
(see existing CC-BY-NC-SA derivative-work note above).

Additional icons harvested for v0.4 universal coverage:

- From [xmb-menu-es-de](https://github.com/anthonycaccese/xmb-menu-es-de) by anthonycaccese (CC-BY-NC-SA 2.0):
  imageviewer.png, pygame.png, n64.png, ...  (list expanded during implementation)

- Generic fallback `_default.png` re-used for systems without dedicated icons:
  ...  (list expanded during implementation)
```

Per-source bulk attribution is sufficient given (a) the upstream license already covers the parent theme as a whole and (b) per-file attribution at this volume would be unmaintainable. If the implementer pulls from a theme not already in CREDITS, that theme gets a new bullet with full attribution.

### Testing

- Run `scripts/populate-fallback-icons.sh` → reports summary, creates new PNGs, no errors
- Diff `art/system-icons/` against the canonical system list → zero missing entries
- Deploy to device → navigate carousel → every system shows an icon (some may be `_default.png` copies)
- The user's previously-observed `ima…` and `pyg…` no longer appear as text
- Re-running `populate-fallback-icons.sh` is idempotent (skips already-existing files)

### Out of scope for v0.4

- Redesigning `_default.png` itself (current upstream version is acceptable)
- Hand-authoring brand-new icons for any system
- Per-system color tinting based on the active colorset
- Auto-update / device-side population (the static-in-repo approach is the only sync mechanism)

## Risks and unknowns

- **Gamecount element name** — known unknown, must be identified before Change 2 files can be authoritatively written. Investigation steps documented in Change 2.
- **Carousel layout on non-1024×768 devices** — the new center at y=0.50 should look fine on any aspect ratio since the position is normalized [0..1]. No specific testing required outside the Brick.
- **Harvest license compatibility** — only confirmed-CC-BY-NC-SA sources are eligible. Implementation must verify per source theme before pulling.
- **System list drift** — Knulli adds/renames systems over time. The static-in-repo list will go stale. The README customization note tells users how to drop in a hand-tuned icon for any new system, which is also the recovery path if the fallback script hasn't been re-run after a Knulli upgrade.
