# v0.12 Gamelist Styles — Design

**Scope:** replace the single v0.11 gamelist with **three user-selectable
styles** behind a new `gamelistStyle` subset, and fix the two composition
faults the shipped card layout has in use.

**Status:** design approved in chat 2026-09-05. Mockups signed off
(`docs/screenshots/v0.12-gamelist-mockups/`, PR #36). No theme XML written yet.

**Branch / PR shape:** implementation on `feat/v0.12-gamelist-styles`, branched
from `main`. PR #36 (mockups + this spec) merges first so the design record is
on `main` before code. Implementation commits, in dependency order:

1. `refactor: split _inc/gamelist.xml into three style files, add gamelistStyle subset`
2. `feat: style A — PSP card recomposed (media above title, bounded description)`
3. `feat: style B — list + details`
4. `feat: style D — box art grid`
5. `docs: §8 subsets table, §10 superseded decisions, README`

---

## 1. Problem

The v0.11 PSP-card gamelist shipped and was verified on-device, but two faults
remain in use:

1. **Text overflow / clipping.** `cardDesc` renders as a full vertical paragraph
   that runs under the help strip on-device (its `<size>` height of 0.10 does
   not clip), and a long genre wraps `cardMetadata`, pushing the stars onto a
   second line.
2. **Wasted space.** The upper-right quadrant and the left column below the card
   are empty. The view does not read as composed the way the system view does.

Navigation was explicitly **not** raised. Three visible rows works in practice,
and the card-vs-cursor decoupling at the list edges has not bitten. Neither is
addressed here.

Separately, the user asked for the card's media to be a **screenshot that
becomes a video after a few seconds**, in the correct aspect ratio.

## 2. Decision

Ship three styles, selectable at runtime:

| Subset value | File | View | Origin |
|:---|:---|:---:|:---|
| **PSP Card** (default) | `_inc/gamelist-card.xml` | `detailed,gamecarousel` | v0.11 card, recomposed |
| **List + Details** | `_inc/gamelist-list.xml` | `detailed,gamecarousel` | `es-theme-PlayStation-X`, RANKING Tier 1 #2 |
| **Box Art Grid** | `_inc/gamelist-grid.xml` | `grid` | `Meringue_Knulli` |

Two styles considered and dropped: `es-theme-minimal` panels and `FakeXMB`
(mockups C and E in PR #36).

### This supersedes two §10 settled decisions

Recorded rather than deleted, per the "do not re-litigate" discipline:

- *"Single PSP-card gamelist; right info panel removed"* (v0.11 / PR #32) —
  superseded 2026-09-05. Reason: the user asked for multiple styles after
  living with the card. Style B does reintroduce a right-hand metadata region.
  Note that `FakeXMB`, the only other XMB theme in the 211-theme render corpus,
  also abandons XMB for its own gamelist.
- *"Three visible game rows"* (v0.9.3 r4, carried into v0.11) — still holds for
  style A. Styles B and D are exempt by construction.

## 3. Mechanism — how one subset switches view type

Verified against the pinned Knulli ES source in the render container
(`es-xmb-harness:knulli-9bbb16a`, `/opt/es`), not assumed:

- `ThemeData::appendFile()` calls `parseVariables()` then `parseTheme()` on
  **every included file's root** (`ThemeData.cpp:2635-2636`).
- `parseTheme()` reads the root `defaultView` attribute into `mDefaultView`
  (`ThemeData.cpp:1329-1330`).
- `ViewController::getGameListView()` substitutes `getDefaultView()` for the
  view preference whenever ES's own `GamelistViewStyle` setting is `automatic`
  (`ViewController.cpp:715-720`), then maps `grid` → `GridGameListView`
  (`ViewController.cpp:742, 780`).

So a subset variant file whose root is `<theme defaultView="grid">` switches the
whole theme to the grid view. Each style file therefore declares its own
`defaultView`:

```xml
<!-- _inc/gamelist-card.xml, _inc/gamelist-list.xml -->
<theme defaultView="detailed">
<!-- _inc/gamelist-grid.xml -->
<theme defaultView="grid">
```

**Extras rebinding holds in all three.** `GridGameListView : public
ISimpleGameListView` (`GridGameListView.h:14`) and calls
`updateThemeExtrasBindings()` (`GridGameListView.cpp:228`), so the v0.11 Path-B
trick — `extra="true"` elements binding `{game:*}`, rebound to the selected game
on cursor change — works in the grid style too.

### Subset declaration

```xml
<subset name="gamelistStyle" displayName="Gamelist Style">
  <include name="PSP Card">./_inc/gamelist-card.xml</include>
  <include name="List + Details">./_inc/gamelist-list.xml</include>
  <include name="Box Art Grid">./_inc/gamelist-grid.xml</include>
</subset>
```

First variant is the default, matching the existing `videoDelay` convention.

### Include order in `theme.xml` — load the style LAST

The style files contain the `<view>` blocks, and `${var}` substitution happens
at element-parse time. If a style parses before `aspect-*.xml` sets the
per-ratio variables, those overrides are silently lost. This is the exact
last-write-wins trap that cost a debug cycle in v0.11 (`icon-size-*.xml`
clobbering aspect overrides).

Required order:

1. `_inc/common.xml`
2. media-fallback includes
3. `colorset` subset
4. **variable-only** subsets — `iconSize`, `titleVisibility`, `videoDelay`, `scrollSpeed`
5. `aspect-*.xml`
6. **`gamelistStyle` subset** ← the view definitions
7. `_inc/system.xml`, `_inc/menu.xml`, remaining subsets

Amend the §8 rule "subsets that set variables consumed by `_inc/gamelist.xml`
MUST be declared before its `<include>`" to name the new ordering explicitly.

### Wave layers are duplicated per style

`_inc/gamelist.xml` already carries a verbatim copy of the three `waveLayer`
elements because of a documented Knulli quirk: storyboard-animated
`extra="true"` elements declared only in `_inc/wave-motion.xml` do not animate
on gamelist views. Each of the three style files needs its own copy inside its
own `<view>` block. This duplication is deliberate; comment it in each file so a
future reader does not "clean it up".

## 4. Style A — PSP Card, recomposed

Reference mockup: `a2-media-centred-i-screenshot.png` (screenshot state) and
`a2-media-centred-ii-video-16x9.png` (video state).

### What changes from v0.11

| Change | Why |
|:---|:---|
| System icon centre `glLogoY` 0.18 → **0.110**, caption `glCaptionY` 0.24 → **0.222** (centre) | The caption was colliding with the icon. |
| Textlist `glListTop` 0.245 → **0.21**, `glListH` 0.69 → **0.75** | Moves the peek rows clear of the enlarged card and the caption while keeping `cardY` on the middle slot. |
| New `cardMedia` `<video>` above the title | Screenshot → video, and it fills the dead upper-right region. |
| Card boxart `cardBoxartW/H` 0.234×0.3125 → **0.22×0.29** | Makes room for the media block above. |
| `cardY` 0.59 → **0.585** | Falls out of the new slot maths. |
| Metadata split across two lines | A long genre can no longer displace the stars. |
| Description becomes a bounded 5-line block, full text width | Cannot reach the help strip. Replaces the narrow marquee strip. |
| Peek titles centred **beneath** their icons | Fills the left column; works in both Strict and Friendly. |

fall back to `<clipRect>` (present on the text element map).

## 7. The media element (shared by A and B)

ES's `VideoComponent` does screenshot-then-video natively, so **on hardware** one
element would be enough. It is nonetheless implemented as a **pair**.

**Corrected 2026-09-05 during implementation.** The render harness's ES binary
contains zero `VideoVlcComponent` symbols and is not linked against `libvlc` —
video support is compiled out of that build, even though the source is listed in
`es-core/CMakeLists.txt`. A `<video>` element therefore draws **nothing** in the
harness: not the video, and not its snapshot either, because `renderSnapshot()`
is never reached. Under a single-element design the entire upper-right region of
style A would be unverifiable in every render we can produce. So an
`<image name="cardScreenshot">` bound to `{game:image}` sits at the same anchor
and envelope at `zIndex 7`, with the video over it at `zIndex 9`. The image
component demonstrably works. Known cost: on device, a game whose video and
screenshot have different aspect ratios may show screenshot edges around the
letterboxed video.

The video element itself keeps the native behaviour:

```xml
<video name="cardMedia" extra="true">
  <path>{game:video}</path>
  <pos>0.6775 0.290</pos>
  <maxSize>${cardMediaW} ${cardMediaH}</maxSize>
  <origin>0.5 0.5</origin>
  <snapshotSource>image</snapshotSource>
  <showSnapshotDelay>true</showSnapshotDelay>
  <showSnapshotNoVideo>true</showSnapshotNoVideo>
  <delay>${videoDelay}</delay>
  <audio>${videoAudioEnabled}</audio>
  <zIndex>8</zIndex>
</video>
```

- `snapshotSource=image` makes the still `{game:image}` — the screenshot.
- `showSnapshotDelay=true` shows it during the `<delay>` window.
  v0.11 left this at its `false` default, which is why a separate `cardBoxart`
  was needed to have anything visible.
- `showSnapshotNoVideo=true` keeps the screenshot forever when a game has no
  scraped video.
- `<delay>` is in **seconds** (`VideoComponent.cpp:282` multiplies by 1000), so
  the existing **Video Delay** subset (Instant / 2 s / 5 s / 10 s) becomes the
  "after a few seconds" control at no cost.
- `<maxSize>` never distorts: `setMaxSize()` is documented in-source as
  *"Never breaks the aspect ratio"* (`VideoComponent.h:95`).

**Fold in the `videoAudio` subset while here.** §8 flags it as targeting the
hidden legacy `md_video` and therefore a no-op. Point it at the new media
element via a `${videoAudioEnabled}` variable.

**Limit, to be documented in the README, not engineered around:** `maxSize`
preserves the *video file's* aspect ratio, not the system's canonical one. A
4:3-padded ScreenScraper clip for a 10:9 Game Boy game renders with its padding
intact. Cropping would need per-system crop rectangles and would mangle
correctly-authored clips; not worth it.

## 7a. Binding vocabulary — verified, not guessed

`FileData::getBindableProperty()` (`FileData.cpp:1880-1990`) resolves
`{game:*}`. Named properties are handled explicitly; anything else falls
through to the metadata list. Confirmed for this build:

| Binding | Notes |
|:---|:---|
| `{game:releaseyear}` | **Use this for the year.** There is no `{game:releasedate:%Y}` format-specifier syntax — an earlier draft of this spec had it wrong. |
| `{game:playercount}` | Normalises `"1-4"` / `"2+"` to a single integer, clamped 1–9. Prefer over raw `{game:players}`. |
| `{game:stars}` | See the warning below. |
| `{game:name}`, `{game:desc}`, `{game:genre}`, `{game:developer}`, `{game:publisher}` | Plain metadata passthrough. |

### ⚠ `{game:stars}` emits filled stars only

```cpp
int stars = round(clamp(0,1, rating) * 5.0);
for (int i = 0; i < stars; i++) str += RATINGSTAR;   // \uF005
```

It returns **only the filled glyphs** — there is no empty-star track. A
4-star game renders as four stars, not "★★★★☆". The round-1 and round-2
mockups all draw a dim fifth star, so **the mockups overstate what ES will
render.**

### ⚠ There is no per-game index binding

`FileData::getBindableProperty()` exposes no `index`, and `{system:total}`
(`SystemData.cpp:2162`) is a whole-library game count, not a cursor position.
The `gamecount` subset only affects the system-view carousel. **The `2 / 10`
position counter drawn in the round-1/2 mockups is not implementable** as a
theme change; that corner stays empty. Recorded so it is not re-attempted.

### Decision: build the five-star track

Approved 2026-09-05. Each style gets a paired element:

```xml
<!-- dim backing track: five literal U+F005, always five -->
<text name="cardStarTrack" extra="true">
  <pos>${cardStarX} ${cardMetaY}</pos>
  <fontPath>${fontLight}</fontPath>
  <fontSize>${cardMetaFontSize}</fontSize>
  <color>${textSecondary}</color>
  <opacity>0.35</opacity>
  <text>&#xF005;&#xF005;&#xF005;&#xF005;&#xF005;</text>
  <zIndex>7</zIndex>
</text>
<!-- filled stars, drawn over the track at the SAME anchor -->
<text name="cardStars" extra="true">
  <pos>${cardStarX} ${cardMetaY}</pos>
  ... identical font, size, origin ...
  <color>${textPrimary}</color>
  <text>{game:stars}</text>
  <zIndex>8</zIndex>
</text>
```

This works because ES does **per-glyph font fallback**: `Font.cpp:274-312`
searches the element's own font, then `:/fontawesome-webfont.ttf`, then
`DroidSansFallbackFull.ttf`. A literal `U+F005` in theme XML therefore
resolves to the same glyph, at the same size and advance width, as the one
`{game:stars}` emits. No `<fontPath>` override is needed.

**Consequence — stars must sit in a fixed column, not inline.** The track is
always five glyphs wide and the filled string is 0–5, so both must be
**left-aligned at the same fixed x**. They cannot flow after a
variable-width genre, and they cannot be right-aligned (that would align the
last *filled* star with the last *track* star). The round-1/2 mockups show
`genre · stars · players` flowing inline; the implementation uses three
fixed columns instead.

This is a net win: it makes the original "a long genre pushes the stars onto
line 2" fault **structurally impossible** rather than merely tuned away, which
is what the v0.11 `cardMetaFontSize` per-ratio overrides were doing.

Clip the genre to its column (`<multiLine>false</multiLine>` plus a bounded
`<size>`) so it cannot reach the star column.

**Column budget at 4:3.** Five glyphs at `cardMetaFontSize` 0.030 measure
≈ 0.114 of screen width, so the star column occupies 0.530 – 0.644. Genre gets
0.385 – 0.520 (clipped at 0.135) and players starts at 0.680. Any per-ratio
change to `cardMetaFontSize` **must** re-check this budget — a larger font
widens the track and will run it into the players column.

## 8. Per-aspect-ratio handling

Each style namespaces its own variables — `card*`, `list*`, `grid*` — so
`aspect-{8x7,3x2,16x9,1x1}.xml` can carry overrides for all three unconditionally.
Only one style file loads, so the other namespaces resolve to unused variables,
which is harmless.

Style A inherits the v0.11 per-ratio work, including the `cardMetaW` /
`cardMetaFontSize` overflow fix. `cardMediaW` / `cardMediaH` are new and need a
per-ratio pass: at 16:9 the media envelope can grow horizontally; at 1:1 it must
shrink vertically or it will collide with the title.

## 9. Verification

**Harness** — `scripts/render.sh` / `render-fixtures.sh`, using the
KNULLI-accurate library (the 60-game slice at `/tmp/library`, not a synthetic one):

- 3 styles × 5 aspect ratios = 15 renders; read every PNG, do not trust exit codes.
- 3 styles × {Boxart, Compact} × {PSP-Faithful, With Titles} for style A.
- A game with no thumbnail and no video → media fallback in every style.
- A long-genre game (e.g. "Shooter / 1st person") → stars stay on line 1.
- A 0-rating game → `{game:stars}` is empty; confirm the dim track still shows five stars and nothing collapses.
- A 5-star game → filled stars exactly cover the track, no track edge peeking out.
- Confirm the literal `&#xF005;` track resolves via font fallback and is not tofu.
- A long-description game → description clips, does not overflow.
- Switch `gamelistStyle` between all three and confirm no element leakage
  between styles.

**On-device** (`./scripts/deploy.sh push`, then `ui.sh reload-theme` from the
system carousel) — the harness cannot show these:

- Screenshot → video handoff actually fires after `${videoDelay}`.
- Video renders at its native aspect ratio, not stretched. **This also
  retro-verifies the v0.11 `<size>` → `<maxSize>` fix, which has never been
  checked on hardware.**
- Description clips at the bounded height instead of running under the help strip.
- Grid style: confirm ES actually selects it, with Gamelist View Style left at
  Automatic and again with it pinned to `detailed` (which should still yield
  grid via the fallback in §10).
- Video audio follows the `videoAudio` subset.

## 10. Risks and limits

| Risk | Severity | Handling |
|:---|:---:|:---|
| User has set ES's Gamelist View Style to `detailed` or `gamecarousel` → Box Art Grid silently does nothing and ES renders an unstyled view | **medium** (downgrade RETRACTED 2026-09-05, empirically disproved) | I downgraded this to low on the reasoning that `ViewController.cpp:697-698` resets an unsupported preference to `automatic`, which then resolves to the theme's `defaultView`. **That reasoning was wrong.** It assumed only the active style file registers views. In fact SIX shared includes register a `detailed,gamecarousel` view unconditionally — `_inc/common.xml:227`, `_inc/wave-motion.xml:23`, `_inc/scroll-speed-{slow,normal,fast}.xml:14`, `_inc/video-audio-{on,off}.xml`. So `hasView("detailed")` and `hasView("gamecarousel")` are ALWAYS true, the reset never fires, and the theme's `defaultView` is ignored. Verified by render: pinning `gamecarousel` with Box Art Grid active produced ES's default unstyled carousel, not the grid. Cannot be fixed by narrowing those includes — `common.xml` legitimately styles shared chrome (the clock) across gamelist views. **Mitigation is documentation:** the README must state that Box Art Grid requires Gamelist View Style = Automatic (ES's own default). |
| Description still does not clip on-device | medium | Fall back to `<clipRect>`. Do not ship an unbounded description again. |
| Include-order regression silently drops aspect overrides | medium | Same class of bug as v0.11. Covered by the 15-render matrix; a wrong-size element at a non-4:3 ratio is the signature. |
| Grid tile scaling / selection not tunable enough to match the mockup | low | `selectionMode` and `imageSizeMode` are present; worst case the selected tile gets a border but no scale-up. |
| Track and filled stars misalign (different font resolution or sub-pixel origin) | low | Both elements must be byte-identical except `text`, `color`, `opacity` and `zIndex`. Verified visually in the render matrix at all five aspect ratios. |
| Three style files drift apart (chrome, wave, `md_*` suppression duplicated 3×) | low | Accepted cost of the Knulli animation quirk. Keep the duplicated blocks byte-identical and comment why. |
