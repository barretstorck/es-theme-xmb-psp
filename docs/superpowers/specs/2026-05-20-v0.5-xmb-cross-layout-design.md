# v0.5 — XMB Cross Layout

**Status:** Design approved 2026-05-20. Implementation pending.

**Builds on:** v0.4 (centered carousel, toggleable game count, universal icon
coverage). v0.4's `colorset` subset, wave background/motion, icon coverage, and
`menu` view are untouched.

## Goal

Reposition the system carousel and reshape the gamelist view so the two screens
read as one continuous PSP XMB cross.

Four user-facing requirements:

1. The system carousel moves up so the icon row sits at 33% from the top.
2. The selected system icon moves to 33% from the left (off-center, XMB-style)
   instead of screen-center.
3. The selected system shows its display name as a text caption directly under
   the icon.
4. After selecting a system, the gamelist view continues the cross: the selected
   icon + caption stay frozen at the same spot while a vertical game menu
   unfurls beneath them and a preview panel fills the right side.

Requirements 1-3 land in the `system` view; requirement 4 in the `detailed`
(gamelist) view. The cross is "continuous" because both views pin the icon to
the same coordinates. The implementation sections below are lettered A-D to keep
them distinct from these numbered requirements.

### Constraint that shapes the design

batocera-emulationstation renders the `system` view and the gamelist views with
separate C++ view classes. The system carousel is bound to `SystemView`;
per-system game lists exist only in the gamelist views. Consequences:

- A literal single-screen XMB cross (horizontal systems scrolling *while* a game
  list is visible) is not possible in theme XML — confirmed in the v0.1
  knulli-port spec and re-confirmed for v0.5. Navigation stays two-stage:
  `system` view <-> `detailed` view, joined by A/B.
- The gamelist view has no system-carousel data binding, so it can only show the
  *currently selected* system's icon — neighbouring system icons cannot appear
  there.

v0.5 therefore *approximates* the cross: the selected icon and caption occupy
identical screen coordinates in both views, so pressing A "freezes" them in
place while the game column fades in. This freeze-in-place continuity is the
design's core trick (Approach A — twin views, shared coordinates).

## Architecture

Approach A — twin-view with shared coordinates. Two ES views stay separate; a
shared set of layout variables guarantees the icon and caption render at the
same point in both.

| Change | File(s) |
|---|---|
| Shared cross-anchor constants | `_inc/common.xml` (modify) |
| System view: carousel reposition + off-center selection + name caption | `_inc/system.xml` (modify) |
| Gamelist view: cross continuation + game column + preview panel | `_inc/gamelist.xml` (modify) |

| README v0.5 banner + screenshots | `README.md`, `docs/screenshots/*.png` (modify) |
| Test macro (optional) | `scripts/ui.sh` (modify, only if needed) |

`theme.xml` is unchanged — both the `colorset` and `gamecount` subsets survive
as-is.

## Tech stack

Unchanged from v0.4: batocera-emulationstation theme XML, `formatVersion 7`. No
new runtime dependencies. Verification uses the repo's existing
`scripts/deploy.sh` and `scripts/ui.sh`.

## The cross anchor

One normalized point drives the layout: the selected system icon is centred at
**(crossX = 0.33, crossY = 0.33)**. The horizontal system bar runs through
y = 0.33; the vertical game column runs down from x = 0.33. The name caption
sits just below at **captionY ~= 0.44**.

```
        x=0.33
          |
 y=0.33 --+[sys] [sys] [SYS] [sys] [sys]--   horizontal system bar
          |      "SNES"                       system-name caption  (y~=0.44)
          |   -----------
          |    Super Mario World     +----------+
          |    F-Zero                |  boxart  |   game preview
          |    Donkey Kong Country   +----------+   panel (right ~40%)
          |    ...                    Released 1991
          |                           Players  1-2
```

These three values live in `_inc/common.xml` `<variables>` (`crossX`, `crossY`,
`captionY`) so the system view and the gamelist view cannot drift apart.
batocera-ES theme XML has no arithmetic, so values that derive from the anchor
(e.g. the carousel container's top edge) are computed once by hand and commented
with their derivation.

Add to the existing `<variables>` block:

```xml
<crossX>0.33</crossX>
<crossY>0.33</crossY>
<captionY>0.44</captionY>
```

Used by both `_inc/system.xml` and `_inc/gamelist.xml`. No other change to
`common.xml`.

## Change B — System view (`_inc/system.xml`)

### Current state (v0.4)

- `<carousel name="systemcarousel">` at `<pos>0 0.35</pos>` `<size>1 0.30</size>`
  -> bar centerline y = 0.50; `<logoAlignment>center</logoAlignment>`; selected
  icon at screen-center x = 0.50.
- No system-name caption (v0.4 removed it for the "PSP-pure" icon-only look).

### New state (v0.5)

**Carousel reposition.** `<pos>0 0.18</pos>` `<size>1 0.30</size>` -> box
centerline y = 0.33 (`0.18 + 0.30/2`). `logoSize` (`0.10 0.14`), `logoScale`
(`1.5`), `maxLogoCount` (`7`) unchanged.

**Off-center selection.** Seat the selected logo at x = `${crossX}` (0.33)
rather than centered. Primary mechanism: the carousel's `logoPos` property —
batocera-ES `THEMES.md` documents it as "set the logo position if it is not
centered." Neighbouring icons flow left and right of the selection (XMB-style:
a couple of visited systems left, upcoming systems right). See Known unknown #1
for the fallback.

**System-name caption.** Re-introduce the `systemInfo` text element (v0.4
confirmed `systemInfo` is batocera-ES's name/count element). Positioned centred
on x = `${crossX}` at y = `${captionY}`, rendering the system display name.
Styling: `${fontLight}`, `fontSize 0.025`, `color ${textSecondary}`,
`alignment center`, transparent background, `zIndex` above the wave.

### Rationale

PSP XMB's category row sits in the upper portion of the screen with the selected
category biased toward the left third, leaving the lower-right for the item
column. y = 0.33 / x = 0.33 reproduces that bias. The caption is XMB-faithful —
XMB labels the selected category — and v0.4 removed it only because v0.4 had no
game column to anchor; v0.5 does.

## Change C — Gamelist view (`_inc/gamelist.xml`, `detailed`)

### Current state (v0.4)

- `<image name="logo">` static system icon, top-left at `<pos>0.04 0.05</pos>`,
  `maxSize 0.12 0.10`, white-tinted (`color ${textPrimary}`).
- `<text name="md_name">` (highlighted game name) large at `<pos>0.18 0.07</pos>`.
- `<textlist name="gamelist">` at `<pos>0.04 0.22</pos>` `<size>0.45 0.65</size>`.
- Preview: `<image name="md_image">` boxart at `<pos>0.55 0.22</pos>`; metadata
  labels/values at x 0.55-0.95, y 0.66-0.76.

### New state (v0.5)

**System icon pinned to the cross anchor.** `<image name="logo">` at
`<pos>${crossX} ${crossY}</pos>`, `<origin>0.5 0.5</origin>`, `maxSize` ~=
`0.15 0.21` (matching the carousel's *scaled* selected logo —
`logoSize 0.10 0.14` x `logoScale 1.5`). Drop the white `color` override so the
icon renders full-colour, identical to the carousel icon.

**System-name caption.** A text element under the icon at y = `${captionY}`,
centred on x = `${crossX}`, styled identically to the system view's caption,
bound to the *source system* display name. See Known unknown #2 — the `detailed`
view needs its own binding for the system name (distinct from `md_name`, the
game name).

**Game column.** `<textlist name="gamelist">` repositioned to unfurl down the
x = `${crossX}` column: top ~= y = 0.50 (just below the caption), height ~= 0.42
(bottom ~= 0.92), `alignment left` with left edge ~= x = 0.25 so game names read
as a column beneath the selected icon. Width ~= 0.30 so it clears the preview
panel. Fonts/colors unchanged from v0.4 (`${fontRegular}`, `${textSecondary}`
primary, `${selectorGlow}` selector, `${textPrimary}` selected).

**Preview panel (right ~40%).** `<image name="md_image">` boxart plus the
`md_releasedate` / `md_players` / `md_rating` metadata block — structure
unchanged from v0.4, positions nudged to read against the new game column.
`<text name="md_name">` (highlighted game name) relocated to serve as the
**header of the preview panel** (the old top-left zone is now the system icon).

**Unchanged:** wave background, top-right clock.

### Rationale

Pinning `logo` and the caption to the same `${crossX}` / `${crossY}` the system
view's selected icon resolves to makes the A-press read as the carousel freezing
while the game column and preview fade in (batocera-ES `fade` transition). The
game `textlist` descending from x = 0.33 is the vertical arm of the cross.

## Change D — Gamecount subset (behaviour-only)

### Current state (v0.4)

`gamecount` subset, Hide (default) / Show. `gamecount-hide.xml` sets
`systemInfo` `visible=false`; `gamecount-show.xml` sets `visible=true` plus a
hard-coded position at `0 0.85`.

### New state (v0.5)

The system-name caption *is* the `systemInfo` element, and it is now always
visible — its position and styling are fixed in `_inc/system.xml` (Change B).
The subset files no longer carry position; they override only whether
`systemInfo` advances from the name to the "X GAMES" count:

- **`gamecount-hide.xml`** (default) — `systemInfo` holds on the system name and
  never advances to the count. Requirement #3 (name always under the icon) is
  always satisfied.
- **`gamecount-show.xml`** — `systemInfo` behaves as batocera default: name,
  then cycling to "X GAMES". Opting in accepts that the name periodically yields
  to the count.

The mechanism for "hold on the name, never cycle" is Known unknown #3.

`theme.xml`'s `<subset name="gamecount">` block is unchanged.

## Known unknowns

Resolve early in implementation by on-device probing, the way v0.4's spec
flagged the `gamecount` element name.

1. **`logoPos` coordinate semantics.** Whether `logoPos` places the selected
   logo at an absolute normalized screen coordinate or relative to the carousel
   container box. Confirm with a short on-device test. **Fallback:** if
   `logoPos` does not seat the selection at x = 0.33, shift the whole carousel
   container instead via `pos` / `origin` so the centered selection point lands
   at 0.33.

2. **Detailed-view system-name binding.** `systemInfo` is a `system`-view
   construct; the `detailed` view needs its own element/metadata key for the
   *source system's* display name (not `md_name`). Survey batocera/Knulli themes
   that show the system name on a gamelist screen; confirm on device.
   **Fallback:** if no clean binding exists, the caption in the detailed view
   may be omitted (the system icon alone still anchors the cross) — but attempt
   the binding first.

3. **"Hold on the name, never cycle" mechanism.** How to keep `systemInfo` on
   the system name without advancing to the count. Candidates: a very large
   carousel `systemInfoDelay`, or `systemInfoCountOnly`. Confirm on device which
   combination yields name-only.

## Testing

Agent-driven verification using the repo's existing scripts, with the user
available as backup.

**Loop:**

1. `scripts/deploy.sh push` — rsync the theme to the device and reload it via
   the `ui.sh reload-theme` macro (Reset Customizations; picks up XML edits
   without an ES restart).
2. `scripts/ui.sh <tokens>` — inject controller input (`left` `right` `a` `b`
   `down` `up`, `sleep:NNN`) to drive the UI into each state.
3. `scripts/deploy.sh shot` — capture the framebuffer to `.dev/last-shot.png`;
   read that PNG to confirm the layout visually.
4. `scripts/deploy.sh logs` — tail the ES log to catch XML parse errors.

**Sequence:**

- Boot shot -> carousel bar centred at y ~= 0.33; selected icon at x ~= 0.33;
  name caption directly under the icon.
- `ui.sh right right` -> shot -> selection still seated at x ~= 0.33; neighbours
  flow correctly; caption tracks the selection.
- `ui.sh a` -> shot -> `detailed` view: system icon + caption unmoved from the
  system view; game `textlist` unfurled down the x ~= 0.33 column; preview panel
  populated for the highlighted game.
- `ui.sh down down` -> shot -> game highlight moves; boxart + metadata update.
- `ui.sh b` -> shot -> back at the system view, icon still aligned.
- `gamecount` Hide vs Show -> toggle via UI Settings -> Theme Configuration ->
  Game Count; shot each -> Hide = name only, Show = name cycles to "X GAMES".
- Regression: `menu` view opens and is readable; a colorset switch still
  applies; the wave still animates.

**Prerequisite.** The loop needs the device reachable on the network (default
`192.168.1.4`, override via `.env.local`) and `.env.local` configured with
`SSHPASS`. If the implementation session has no LAN route to the device,
verification falls back to user-driven testing.

**Optional tooling.** If toggling the `gamecount` subset proves to be a long
menu path, add a macro to `scripts/ui.sh` (the script already supports macro
expansion via `macro_expand`).

## Out of scope

- True single-screen XMB navigation (horizontal scroll while a game list is
  visible) — requires C++ changes to batocera-emulationstation.
- Showing neighbouring system icons in the gamelist view — the gamelist view has
  no system-carousel data binding.
- `gamecarousel`, `grid`, `video`, `basic` gamelist view types.
- Aspect ratios other than 4:3 / 1024x768.
- New or redrawn artwork.
- Fixing the wave-resets-on-carousel-navigation limitation.

## Risks and unknowns

- The three Known unknowns above — each has a fallback or is non-blocking.
- **Carousel layout on non-1024x768 devices** — positions are normalized
  [0..1]; the 33%/33% anchor scales, but v0.5 is validated only on the Brick,
  consistent with prior versions.
- **`fade` transition smoothness** — the freeze-in-place effect depends on the
  `system` -> `detailed` transition not visibly jumping the icon. If the
  transition is jarring, evaluate `instant` vs `fade` during testing; cosmetic,
  not blocking.
