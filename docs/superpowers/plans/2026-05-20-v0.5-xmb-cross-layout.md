# v0.5 — XMB Cross Layout — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise the system carousel to a 33%-from-top bar with the selected icon at 33% from the left, label it with the system name, and reshape the detailed view so the selected icon + caption stay pinned while a vertical game menu unfurls beneath them — an approximated PSP XMB cross.

**Architecture:** Approach A — twin views (`system`, `detailed`) kept separate but sharing one set of cross-anchor coordinates (`crossX`/`crossY`/`captionY`) so the selected icon and caption render at the same screen point in both. Pressing A "freezes" the icon in place while the game column fades in. Pure theme XML, `formatVersion 7`.

**Tech Stack:** batocera-emulationstation theme XML (`formatVersion 7`). `xmllint` for XML well-formedness. Deployment + verification via the repo's existing `scripts/deploy.sh` (push/shot/logs) and `scripts/ui.sh` (controller-input injection).

**Spec:** `docs/superpowers/specs/2026-05-20-v0.5-xmb-cross-layout-design.md`

**Branch:** `v0.5-xmb-cross-layout` (already created; contains the spec commit).

## Operating notes for the implementer

- **Working directory:** the repo root (in the current environment, `/tmp/es-theme-xmb-psp`). All paths below are relative to it.
- **XML validation:** after every XML edit run `xmllint --noout <file>` (exit 0 = well-formed). If `xmllint` is unavailable, use `python3 -c "import xml.dom.minidom,sys; xml.dom.minidom.parse(sys.argv[1])" <file>` instead.
- **Spec change letters:** the spec labels its four implementation changes A–D. This plan's numbered tasks reference them ("implements spec Change B").
- **Device verification — determine the mode once, before Task 2:**
  - Run `./scripts/deploy.sh shell <<<'echo reachable'`. If it prints `reachable`, the **agent-driven loop** is available:
    1. `./scripts/deploy.sh push` — rsync the theme to the device and reload it (`ui.sh reload-theme` macro; no ES restart).
    2. `./scripts/ui.sh <tokens>` — inject input (`left right a b up down`, `sleep:NNN`) to reach the state under test.
    3. `./scripts/deploy.sh shot` — pull a framebuffer screenshot to `.dev/last-shot.png`.
    4. **Read `.dev/last-shot.png`** with the Read tool and confirm the layout visually.
    5. `./scripts/deploy.sh logs` — tail the ES log if something looks broken.
  - If the device is unreachable or `.env.local` (device IP + `SSHPASS`) is absent, switch every "Verify on device" step to **user-driven**: tell the user which files changed, ask them to deploy + reload, and ask them to confirm the specific checks listed. Do not proceed past a verification step until confirmed.
- **If a verification fails:** debug per `superpowers:systematic-debugging`. Theme positioning is iterative — re-screenshotting after a numeric tweak is expected and fine.
- **Frequent commits:** one commit per task, message prefixed `v0.5 task N:`, ending with the `Co-Authored-By` trailer shown in each task.
- **No pushing:** all commits/merges/tags in this plan are local. Pushing to the remote is left to the user.

- Modify: `_inc/gamecount-show.xml` (full rewrite)

```xml

<!--
  es-theme-xmb-psp - "Game Count: Hide" (default).
  The system-name caption (systemInfo) is defined and positioned in
  _inc/system.xml. This subset only controls whether the caption advances
  from the system name to the "X GAMES" count: Hide pushes the carousel's
  systemInfoDelay far into the future, so the caption holds on the name.
  Selected via UI Settings > Theme Configuration > Game Count > Hide.

  <formatVersion>7</formatVersion>
  <view name="system">
    <carousel name="systemcarousel">
      <systemInfoDelay>99999999</systemInfoDelay>
    </carousel>
  </view>
</theme>
```
