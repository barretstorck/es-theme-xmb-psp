# v0.7 — Gamelist Refinements & ES Menu Re-skin — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refine the gamelist views (carousel label styling, carousel sizing and position with a no-peek constraint, a widened right info panel, a larger description font), bring the gamelist wave animation to parity with the system view, and re-skin the EmulationStation Start-button menu to follow the active PSP colorset.

**Architecture:** Theme XML only (`formatVersion 7`). Tasks land in spec order: the three gamecarousel changes, the right-panel changes, the wave-parity fix, then the menu re-skin (a discovery spike to settle build unknowns, then the re-skin itself). The two gamelist styles already share one `<view name="detailed,gamecarousel">` block; right-panel changes go there so the styles cannot drift.

**Tech Stack:** batocera-emulationstation theme XML. No automated test framework — each task is verified by (a) XML well-formedness via `python3` (`xmllint` is absent) and (b) on-device screenshot inspection against the task's acceptance criteria. Deployment and verification via `scripts/deploy.sh` and `scripts/ui.sh`.

**Spec:** `docs/superpowers/specs/2026-05-21-v0.7-gamelist-menu-refinement-design.md`

**Branch:** `v0.7-gamelist-menu` (already created; contains the spec commit `28d0992`).

## Operating notes for the implementer

- **Working directory:** the repo root (in the current environment, `/tmp/es-theme-xmb-psp`). All paths are relative to it. Branch `v0.7-gamelist-menu` is checked out — do NOT switch branches.
- **XML validation:** after every XML edit, run
  `python3 -c "import xml.dom.minidom,sys; xml.dom.minidom.parse(sys.argv[1])" <file>`
  (exit 0 = well-formed). `xmllint` is not installed.
- **Device config:** `scripts/deploy.sh` and `scripts/ui.sh` read `.env.local` at the repo root (gitignored: `DEVICE_IP`, `DEVICE_USER`, `THEME_NAME`, `SSHPASS`). The device is reachable; the theme is the active theme.
- **Device deploy/verify loop:**
  1. `./scripts/deploy.sh sync` — rsyncs theme files to the device.
  2. `./scripts/ui.sh reload-theme` — opens Main Menu → User Interface Settings → Theme Configuration → Reset Customizations. Reset is what forces ES to re-read theme files from disk; toggling a subset only re-applies a cached parse and will NOT pick up edited files.
  3. `./scripts/deploy.sh shot` — captures a screenshot to `.dev/last-shot.png`.
  4. **Read `.dev/last-shot.png`** to verify the result.
- **Reset Customizations resets the theme subsets to defaults.** After every `reload-theme`:
  - the colorset returns to **January Blue**;
  - the **Gamelist View Style** returns to its default. To verify the `gamecarousel` view you must re-select it: Main Menu → User Interface Settings → Theme Configuration → Gamelist View Style → `GAMECAROUSEL`.
  - To enter a system's gamelist from the system carousel, press `a` (`./scripts/ui.sh a`).
- **`ui.sh` input injection:** `./scripts/ui.sh <tokens>` injects controller input. Tokens: `a b x y l r l2 r2 start select hotkey up down left right sleep:NNN`. TRIMUI Brick uses `start`=315, `select`=314.
- **NEVER reboot to reload the UI.** Rebooting risks the device hanging on the Knulli Scarab boot screen. Only reboot if you detect an actual crash loop. To exit a launched game, SSH in and run `knulli-es-swissknife --emukill`.
- **Screenshots work with the screen backlight off** — `knulli-screenshot`/`fbgrab` read the framebuffer.
- **On-device tuning is expected.** All `pos`/`size`/`logoSize`/`logoScale`/`fontSize` values in this plan are starting points to be refined by screenshot. The acceptance criterion, not the literal number, is what must be met.
- **Frequent commits:** one commit per task, message prefixed `v0.7 task N:`, ending with the `Co-Authored-By` trailer shown in each task.
- **No pushing:** all commits, the merge, and the tag are local. Pushing is left to the user.

## Task 2: Gamecarousel image size, position, and the no-peek constraint

Implements spec Changes 2 and 3. The selected game image is sized to match the pinned system icon; the carousel is repositioned so the selected game sits below the icon and caption; and **no part of any game image may ever be visible peeking out from behind the system icon**.

These changes are tuned together because the no-peek constraint depends jointly on image size, carousel position, slot spacing, and `maxLogoCount`.

**Geometry facts:**
- The pinned system icon `logo` displays within `maxSize 0.15 0.21`, centred at `crossX 0.24`, `crossY 0.291`. Its bottom edge sits near `y ≈ 0.291 + 0.21/2 = 0.396`.
- The `systemName` caption top is `captionY 0.401`, height ~`0.055`, bottom near `y ≈ 0.456`.
- Screen is 1024x768 (4:3).

**Files:**
- Modify: `_inc/gamelist.xml` (`<gamecarousel name="gamecarousel">` element; `<image name="logo">` `zIndex`)

- [ ] **Step 1: Raise the system icon above the carousel**

In `_inc/gamelist.xml`, in the shared `<view name="detailed,gamecarousel">` block, change the `<image name="logo">` element's `zIndex` from `5` to `8`:
```xml
    <image name="logo">
      <path>./art/system-icons/${system.theme}.png</path>
      <pos>${crossX} ${crossY}</pos>
      <origin>0.5 0.5</origin>
      <maxSize>0.15 0.21</maxSize>
      <zIndex>8</zIndex>
    </image>
```
This guarantees the icon draws over the carousel (the carousel keeps `zIndex 5`). The `systemName` caption stays at `zIndex 6`; raising the icon to `8` keeps it above both.

- [ ] **Step 2: Apply the mechanism-1 (straddle) geometry to the gamecarousel**

In `_inc/gamelist.xml`, change the `<gamecarousel name="gamecarousel">` element's geometry. Starting values (selected image ≈ system icon size; selected slot centred below icon+caption):
```xml
    <gamecarousel name="gamecarousel">
      <type>vertical</type>
      <imageSource>thumbnail</imageSource>
      <pos>0.08 0.16</pos>
      <size>0.32 0.86</size>
      <origin>0 0</origin>
      <color>00000000</color>
      <logoSize>0.111 0.155</logoSize>
      <logoScale>1.35</logoScale>
      <logoAlignment>center</logoAlignment>
      <maxLogoCount>3</maxLogoCount>
      <textColor>${textPrimary}</textColor>
      <selectedTextColor>${textPrimary}</selectedTextColor>
      <fontPath>${fontLight}</fontPath>
      <fontSize>0.030</fontSize>
      <zIndex>5</zIndex>
    </gamecarousel>
```
Rationale for the starting values:
- `logoSize 0.111 0.155` x `logoScale 1.35` ≈ `0.150 x 0.209` — the selected image matches the icon's `0.15 0.21` box. Unselected neighbours render at `0.111 0.155` (smaller), keeping the carousel's selected-is-larger emphasis.

- `maxLogoCount 3` shows the selected slot plus one above and one below.
