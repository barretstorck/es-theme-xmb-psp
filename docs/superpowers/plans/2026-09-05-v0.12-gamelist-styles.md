# v0.12 Gamelist Styles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single v0.11 gamelist with three user-selectable styles — PSP Card (recomposed), List + Details, and Box Art Grid — behind a new `gamelistStyle` theme subset.

**Architecture:** `_inc/gamelist.xml` splits into three mutually-exclusive style files, each declaring its own root `defaultView` attribute and its own `<view>` block. ES's `ThemeData::appendFile()` runs `parseTheme()` on every include, so the `defaultView` on a subset variant's root selects the view type; `ViewController` honours it whenever the user's own `GamelistViewStyle` is `automatic` or names a view the active style does not define. Exactly one style file is ever included, so the styles cannot leak elements into each other.

**Tech Stack:** batocera-emulationstation theme XML (formatVersion 7), pinned Knulli ES `9bbb16a`; Docker render harness (`scripts/render.sh`); bash smoke tests (`scripts/tests/`); Python 3 + PIL for mockups.

**Spec:** `docs/superpowers/specs/2026-09-05-v0.12-gamelist-styles-design.md`

## Global Constraints

- **Reference geometry is 4:3 1024×768.** All `<pos>`/`<size>`/`<fontSize>` values are normalised 0.0–1.0; `fontSize` normalises to screen **height**.
- **Include order in `theme.xml` is load-bearing.** `common.xml` → media-fallback → `colorset` → variable-only subsets (`iconSize`, `titleVisibility`, `videoDelay`, `scrollSpeed`) → `aspect-*.xml` → **`gamelistStyle` subset** → `system.xml` / `menu.xml`. Variables resolve at element-parse time; a view parsed before `aspect-*.xml` silently loses its per-ratio overrides. This is the v0.11 `icon-size-*.xml` clobbering bug.
- **Never re-introduce `<horizontalAlignment>`.** It is a typo for `<alignment>` and generates ~80 parse warnings per render.
- **`textPrimary` is `FFFFFF` always.** Do not introduce a new primary text colour.
- **Wave layers must be duplicated inside each style's `<view>` block.** Knulli quirk: storyboard-animated `extra="true"` elements declared only in `_inc/wave-motion.xml` do not animate on gamelist views. Keep the three copies byte-identical.
- **Bottom `0.94`–`1.00` is the helpsystem strip; top `0.00`–`0.10` is the status bar.** No content in either.
- **Licence header** on every new `_inc/*.xml`: `CC-BY-NC-SA 2.0. See CREDITS.md.`
- **Every render must be opened and looked at.** A zero exit code from `render.sh` is not evidence. "Render succeeded" is not verification.
- **Do not invent `{game:*}` bindings.** Verified to exist on this build: `name`, `desc`, `genre`, `developer`, `publisher`, `thumbnail`, `image`, `video`, `stars`, `playercount`, `releaseyear`. Verified NOT to exist: any per-game `index`, and `{game:releasedate:%Y}` format-specifier syntax. `FileData::getBindableProperty()` handles named properties explicitly and falls through to the metadata list for everything else (`FileData.cpp:1880-1990`); an unknown name yields `BindableProperty::Null` and renders empty, silently.
- **Render against BOTH libraries. Neither alone is sufficient.**
  - `./scripts/render-fixtures.sh` uses `tests/fixtures/library/` — 26 files, purpose-built degenerate cases (`no-thumb`, `no-video`, `no-genre`, `no-desc`, `zero-metadata`, `unscraped-game`). Its longest description is **74 characters** and its longest genre is `"Shoot 'em up"`, so it **cannot** exercise the description-overflow or genre-column fixes that are the point of v0.12.
  - `./scripts/render.sh --library /tmp/library` uses the KNULLI-accurate 60-game slice — 364 files, real ScreenScraper metadata, real box art and screenshots, longest description **1252 characters**. This is the only way to see the overflow behaviour.
  - Every render step below is listed twice for this reason. If `/tmp/library` is missing, say so in your report and run fixtures only — do **not** silently skip it, and do **not** claim the overflow fix is verified.
- **Neither library contains any video files.** The screenshot→video handoff cannot be verified in the harness at all. Verify the static snapshot path only; the handoff is on the on-device checklist.

check() { # check <description> <condition-exit-code>

CARD="${REPO_ROOT}/_inc/gamelist-card.xml"
COMMON="${REPO_ROOT}/_inc/common.xml"

var() { # var <name> -> value from common.xml
  grep -oP "(?<=<$1>)[^<]*" "${COMMON}" | head -1

# Slot centres are FORCED even by <lines>3</lines>:
#   centre_i = glListTop + glListH * (i + 0.5) / 3

import sys
top, h, cardy = (float(x) for x in sys.argv[1:4])

src = open(common).read()
def resolve(tok):
    """Turn '${name}' into its numeric value from common.xml; pass numbers through."""
    m = re.fullmatch(r"\$\{(\w+)\}", tok.strip())
